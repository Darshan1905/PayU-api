Mswipe Middleware API

Base URL: https://connect.pavokart.com  ·  API Key: mswipe-pavokart-demo-key  ·  Version 1.0.3

Overview

Same domain as PayU (connect.pavokart.com). Mswipe routes are proxied to the Mswipe Laravel app. Flow: Client → Middleware → WordPress (pavokart.com) → Mswipe PBL → checkoutUrl.

MethodEndpointDescription
GET/api/mswipe/productsProduct catalog
POST/api/mswipe/create-orderCreate WC order + payment link
POST/api/mswipe/initiateAmount-only payment link
POST/api/mswipe/statusPayment status
GET/api/mswipe/notificationsWebhook log
POST/webhook/mswipeMswipe callback (no API key)

API Key

X-API-Key: mswipe-pavokart-demo-key

Required on every /api/mswipe/* request. IP whitelist also applies. Webhook does not use API key.

Headers (all API requests)

Accept: application/json
X-API-Key: mswipe-pavokart-demo-key

For POST requests also add: Content-Type: application/json

Auto customer details (create-order)

If customer is omitted or incomplete, Indian name, mobile, email, and address are auto-generated. Auto-generated emails always use @gmail.com (e.g. rahul.sharma42@gmail.com). Shipping mirrors billing. Response includes customer and customerAutoGenerated: true.

1. List products

GET/api/mswipe/products?page=1&per_page=50

Full URL
https://connect.pavokart.com/api/mswipe/products?page=1&per_page=50
Headers
Accept: application/json
X-API-Key: mswipe-pavokart-demo-key

Optional query: search. Use product id / variation id in create-order.

2. Create order — simple product

POST/api/mswipe/create-order

Full URL
https://connect.pavokart.com/api/mswipe/create-order
Headers
Content-Type: application/json
Accept: application/json
X-API-Key: mswipe-pavokart-demo-key
Body
{
  "lineItems": [
    { "productId": 123, "quantity": 1 }
  ]
}
Success response (shape)
{
  "status": true,
  "respCode": 2000,
  "respMessage": "Order created and payment link generated",
  "data": {
    "orderId": 12345,
    "txnId": "IPG...",
    "checkoutUrl": "https://...",
    "paymentUrl": "https://...",
    "amount": "499.00",
    "customerAutoGenerated": true,
    "customer": { "email": "rahul.sharma42@gmail.com" }
  }
}

Open checkoutUrl (or paymentUrl) for the customer to pay on Mswipe Pay-By-Link.

3. Create order — variable product

POST/api/mswipe/create-order

Body
{
  "lineItems": [
    {
      "productId": 20600,
      "variationId": 20601,
      "quantity": 1
    }
  ]
}

variationId is required for variable products. Get IDs from GET /products.

4. Create order — mixed cart

POST/api/mswipe/create-order

Body
{
  "lineItems": [
    { "productId": 123, "quantity": 1 },
    { "productId": 20600, "variationId": 20601, "quantity": 2 }
  ]
}

5. Payment status

POST/api/mswipe/status

Full URL
https://connect.pavokart.com/api/mswipe/status
Headers
Content-Type: application/json
Accept: application/json
X-API-Key: mswipe-pavokart-demo-key
Body
{
  "txnId": "IPG000000021511"
}

Use txnId from create-order. Typical payment status: 1 = success, 0 = failed, 2 = pending.

7. Initiate payment (amount only)

POST/api/mswipe/initiate

Full URL
https://connect.pavokart.com/api/mswipe/initiate
Headers
Content-Type: application/json
Accept: application/json
X-API-Key: mswipe-pavokart-demo-key
Body
{
  "requestAmount": 499.00,
  "productInfo": "Payment"
}

Does not create a WooCommerce catalog order — amount-only payment link.

8. Webhook (Mswipe → middleware)

POST/webhook/mswipe

Full URL
https://connect.pavokart.com/webhook/mswipe

Configure this URL in the Mswipe merchant portal. No X-API-Key. Middleware stores the notification and can forward to your client callback.
