Airpay Middleware API

Base URL: https://connect.pavokart.com  ·  API Key: airpay-pavokart-demo-key  ·  Simple Transaction v1.0.2

Overview

Same domain as PayU / Mswipe (connect.pavokart.com). Flow: Client → Middleware → WordPress (pavokart.com) → Airpay OAuth + hosted checkout → customer pays on payments.airpay.co.in → return / IPN. No auto name/address generator — send customer fields in the request (or use WooCommerce checkout).

MethodEndpointDescription
POST/api/airpay/initiateCreate hosted payment redirect URL
POST/api/airpay/statusVerify payment status
GET/api/airpay/notificationsWebhook / IPN log
POST/webhook/airpayAirpay IPN (no API key)

API Key

X-API-Key: airpay-pavokart-demo-key

Required on every /api/airpay/* request. IP whitelist also applies. Webhook does not use API key.

Headers (all API requests)

Accept: application/json
X-API-Key: airpay-pavokart-demo-key

For POST requests also add: Content-Type: application/json

Architecture

Client / Postman / Checkout
  → https://connect.pavokart.com/api/airpay/*
  → https://pavokart.com/wp-json/airpay/v1/*
  → Airpay OAuth + Simple Transaction form
  → https://payments.airpay.co.in/pay/v4/?token=...
  → return: /airpay/return/success|failure
  → IPN: /webhook/airpay

1. Initiate payment

POST/api/airpay/initiate

Full URL
https://connect.pavokart.com/api/airpay/initiate
Headers
Content-Type: application/json
Accept: application/json
X-API-Key: airpay-pavokart-demo-key
Body
{
  "requestAmount": 10.00,
  "firstName": "Rahul",
  "lastName": "Sharma",
  "email": "rahul@example.com",
  "phone": "9876543210",
  "callbackUrl": "https://pavokart.com/wp-json/airpay/v1/ipn"
}
Optional fields
txnId, address1, udf1,
successRedirectUrl, failureRedirectUrl,
successReturnUrl, failureReturnUrl, returnUrl
Success response (shape)
{
  "status": true,
  "respCode": 2000,
  "respMessage": "Payment link generated",
  "data": {
    "txnId": "AP123T250910120000",
    "checkoutUrl": "https://pavokart.com/wp-json/airpay/v1/redirect?t=...",
    "paymentUrl": "https://pavokart.com/wp-json/airpay/v1/redirect?t=...",
    "amount": "10.00",
    "status": "PENDING"
  }
}

Open checkoutUrl (or paymentUrl) in the browser. Customer is redirected to Airpay hosted payment page (UPI / Net Banking / Wallets / EMI as enabled on the merchant).

2. Payment status

POST/api/airpay/status

Full URL
https://connect.pavokart.com/api/airpay/status
Headers
Content-Type: application/json
Accept: application/json
X-API-Key: airpay-pavokart-demo-key
Body
{
  "txnId": "AP123T250910120000"
}

You may also send orderid instead of txnId. Use the id returned from initiate.

Success response (shape)
{
  "status": true,
  "respCode": 2000,
  "respMessage": "Transaction status fetched successfully",
  "paid": true,
  "data": {
    "txnId": "AP123T250910120000",
    "paymentId": "123456",
    "status": "success"
  }
}

3. Notifications

GET/api/airpay/notifications?limit=20

Full URL
https://connect.pavokart.com/api/airpay/notifications?limit=20
Headers
Accept: application/json
X-API-Key: airpay-pavokart-demo-key

Returns recent IPN / webhook notifications stored by the middleware. Max limit = 100.

4. Webhook / IPN (Airpay → middleware)

POST/webhook/airpay

Full URL
https://connect.pavokart.com/webhook/airpay

Configure this URL in the Airpay merchant panel as the IPN callback. No X-API-Key. Middleware stores the notification, can update the transaction, and proxies to WordPress /wp-json/airpay/v1/ipn.

Example payload (simulation)
{
  "orderid": "AP123T250910120000",
  "ap_transactionid": "123456",
  "amount": "10.00",
  "transaction_status": 200,
  "transaction_payment_status": "SUCCESS",
  "message": "Success",
  "chmod": "pg",
  "merchant_id": "370405",
  "ap_SecureHash": "0"
}

Airpay panel configuration (avoid invalid domain)

Domain URL, Response URLs, and IPN must all use the same host (pavokart.com). Do not send connect.pavokart.com as Response/IPN to Airpay.
